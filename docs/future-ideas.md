# Iteration — Future Ideas

> 이 문서는 현재 확정된 구현 명세가 아니라, 향후 플레이테스트 결과에 따라 검토할 게임플레이 아이디어를 정리한 것이다.
> 구현 전에 기존 시스템과 충돌하는지 확인하고, 현재 구현된 시스템을 우선한다.
>
> 완료된 기능이나 모델은 이 문서에 다시 기록하지 않는다.

## 이 문서와 현재 빌드의 어긋난 곳 (2026-09-02 정리)

리포 루트에 untracked로 있던 문서를 `docs/`로 옮기면서, 이미 사실이 아닌 항목을 표시했다.
**아래 세 항목은 아이디어가 아니라 상태 표시이고, 나머지 절은 예전 그대로 후보다.**

- **§10 (Ghost와 도구 시스템) 은 미래 계획이 아니라 이미 출시된 규칙이다.** `requirePopTool`,
  `KeyLock`, `HoldingEquipped()` 로 구현되어 있고 근거는 `docs/decisions.md`(2026-08-11), 규칙 자체는
  `CLAUDE.md` §4. 이 절은 무엇이 왜 그렇게 되었는지의 기록으로만 읽을 것 — **여기를 고쳐도 게임은 안 바뀐다.**
- **§13 (Room 확장) 은 무효다.** Room4를 뒤로 밀고 `4 * RoomPitch` 에 새 방을 놓는다는 계획은
  방 여섯 개가 한 복도에 늘어선 지금 구조도, 사이클이 층으로 쌓이는 지금 건물도 설명하지 못한다.
  방을 늘리는 현재 규칙은 `docs/cycle-design.md` 와 `TODO.md` 에 있다. §13의 **디자인 원칙**
  ("거리 대신 iteration 비용을 늘린다") 만 살아 있다.
- **§7 (숫자 자물쇠) 은 게임 안에 없고, 지을지 말지 결정되지 않았다.** 지식으로 푸는 자물쇠는
  한 번 알면 iteration이 일을 줄여주지 않아 이 게임의 축적 규칙이 유일하게 깨지는 퍼즐 모양이고,
  같은 문서 §14("최종 iteration에는 새 조작을 넣지 않는다")와도 정면으로 부딪친다. **짓기 전에
  결정해야 하는 항목이며, 결정 전에는 아무것도 구현하지 않는다.**

## 1. 핵심 게임플레이 방향

- 게임의 핵심은 **이전 iteration의 내가 사라지지 않고 계속 누적되는 것**이다.
- 플레이어는 반복할수록 과거의 자신들과 협력하여 혼자서는 할 수 없는 작업을 수행한다.
- 최종 iteration에서는 **Ghost들이 필요한 모든 작업을 이미 수행하고, 현재 플레이어는 아무것도 하지 않고 탈출까지 걸어가는 방향​**을 의도한다.
- 마지막 walk-through는 "할 일이 없어서 기다리는 구간"이 아니라, 지금까지 플레이어가 만든 모든 iteration이 완성되어 작동하는 것을 보여주는 **보상/클라이맥스 구간**으로 설계한다.
- 최종 iteration에서는 새로운 퍼즐이나 새로운 요구사항을 추가하지 않는다.
- 최종 iteration에서는 이전 Ghost들이 버튼, 밸브, 도구 사용, 문 개방 등의 작업을 수행하고 현재 플레이어는 그 결과를 따라가며 탈출한다.
- 마지막에는 여러 Ghost가 각자의 위치에서 동시에 작업하는 모습을 플레이어가 직접 지나가면서 볼 수 있도록 한다.

## 2. 누적 작업량 퍼즐

여러 iteration에 걸쳐 같은 작업을 반복하여 요구량을 채우는 퍼즐을 추가한다.

### 기본 방향

- 한 번의 iteration에서 완료할 수 없는 작업량을 요구한다.
- 이전 iteration의 Ghost들이 같은 작업을 반복한다.
- iteration이 쌓일수록 작업량이 누적된다.
- 충분한 iteration이 쌓이면 목표가 완료된다.
- 단순히 클릭 횟수를 늘리는 방식보다는 **Ghost 간 역할 분담**을 활용한다.

### 후보

- 나무 베기
- 수족관에 물 채우기
- 대형 기계 작동
- 기타 여러 명의 반복 작업이 필요한 장치

## 3. 나무가 있는 방

나무를 이용한 대형 누적 작업 퍼즐.

### 공간 구조

- 나무가 있는 방은 **길고 기다란 형태의 방**으로 구성한다.
- 방의 진행 방향을 거대한 나무가 막고 있다.
- 나무를 제거해야 반대편으로 이동할 수 있다.
- 따라서 나무는 단순한 장식물이 아니라 **방을 가로막는 물리적인 진행 장벽**이다.
- 플레이어는 여러 iteration을 거치면서 나무를 베어 길을 확보한다.

### 도끼

- 방 안에는 **여러 개의 도끼가 배치되어 있다.**
- 한 명의 플레이어만 도끼를 사용하는 것이 아니라 여러 Ghost가 각각 도끼를 사용할 수 있도록 한다.
- 각 iteration에서 플레이어가 도끼를 들고 나무를 베었던 행동은 이후 Ghost가 반복한다.
- 여러 Ghost가 동시에 나무를 베는 모습이 최종적으로 연출된다.

### 목표

```text
Iteration 1
→ 플레이어가 도끼를 들고 나무를 벰

Iteration 2
→ Ghost 1이 같은 위치에서 나무를 벰
→ 현재 플레이어가 다른 위치에서 추가로 작업

Iteration 3+
→ 여러 Ghost가 각자의 위치에서 나무를 계속 벰

충분한 작업량 누적
→ 나무가 쓰러짐
→ 길이 열림
→ 다음 공간으로 이동 가능
```

### 최종 iteration

- Ghost들이 모두 각자의 위치에서 나무를 베고 있다.
- 현재 플레이어는 더 이상 도끼를 사용할 필요가 없다.
- 플레이어가 방을 걸어가면서 여러 Ghost가 나무를 베는 모습을 확인한다.
- 나무가 쓰러지고 길이 열린다.
- 이 장면은 **지금까지 쌓아온 iteration의 결과를 직접 확인하는 보상**으로 활용한다.

## 4. 동시 작업 퍼즐

한 사람이 동시에 여러 위치에 있을 수 없다는 게임의 핵심을 활용한다.

예:

- 레버 A를 계속 유지
- 버튼 B를 누름
- 밸브 C를 조작
- 문 D를 열어둠

각각을 서로 다른 iteration의 Ghost가 담당하도록 한다.

```text
Iteration 1
Ghost 1 → A

Iteration 2
Ghost 1 → A
Ghost 2 → B

Iteration 3
Ghost 1 → A
Ghost 2 → B
Ghost 3 → C

Iteration 4
Ghost 1 → A
Ghost 2 → B
Ghost 3 → C
Ghost 4 → D

→ 현재 플레이어가 통과
```

- 단순히 Ghost 수가 많아지는 것이 아니라 **각 Ghost가 서로 다른 역할을 수행하는 구조**를 우선한다.
- 시간 순서가 필요한 퍼즐도 검토한다.
  - A를 누르면 일정 시간 후 B 활성화
  - B 이후 C가 일정 시간 동안만 활성화
  - 이전 iteration의 행동이 현재 iteration의 행동과 정확히 맞물리는 구조

---

## 5. 수족관에 물 채우기

나무 베기와 유사한 **누적 작업량 기반 퍼즐**.

- 수족관에 일정량 이상의 물을 채워야 한다.
- 여러 iteration의 행동이 누적되어 목표량을 채운다.
- 단순히 물을 반복해서 운반하는 것보다 여러 역할을 분담하는 방향을 우선 검토한다.

가능한 역할:

- 밸브 열기
- 물통 채우기
- 물통 운반
- 수족관에 물 붓기
- 펌프 작동

Ghost들이 서로 다른 작업을 반복하여 최종적으로 수족관을 채운다.

## 6. Room2 확장

현재 Room2의 풍선/열쇠 구조를 확장하는 아이디어.

- 열쇠 하나만 두지 않고 여러 물체/장치에 관련된 요소를 배치한다.
- Room2에서 좌우 방향으로 새로운 문/통로를 추가한다.
- 기존 Room2의 단일 진행 경로를 확장하여 여러 방향으로 탐색할 수 있도록 한다.
- 확장된 공간은 단순 이동 거리를 늘리기보다 **추가 iteration을 요구하는 퍼즐**을 배치하는 방향을 우선한다.

## 7. 숫자 단서 → 최종 자물쇠

> **미구현이고 결정 전이다.** 문서 앞머리의 정리 항목을 먼저 볼 것 — §14와 충돌한다.

여러 방에서 숫자 단서를 수집하고 최종 탈출방에서 하나의 숫자 자물쇠를 해결하는 구조.

```text
Room 1 → 숫자 단서 A
Room 2 → 숫자 단서 B
Room 3 → 숫자 단서 C
Room 4 → 숫자 단서 D

Final Room
→ 숫자 자물쇠
→ A-B-C-D 입력
→ 탈출
```

- 숫자는 별도의 UI로만 제공하지 않고 방 안의 환경과 자연스럽게 연결한다.
- 후보:
  - 시계
  - 실험 번호
  - 침대 번호
  - 모니터
  - 문서
  - 벽의 표시
  - 퍼즐 완료 후 나타나는 숫자

## 8. 체스 퍼즐

한 방에 체스판과 여러 체스 말을 배치한다.

- 체스 말은 방 곳곳에 흩어져 있다.
- 플레이어가 체스판에 올바른 말을 올바른 위치에 배치한다.
- 성공하면:
  - 문이 열린다.
  - 숫자 단서가 나타난다.
  - 다음 퍼즐이 활성화된다.
- 실제 체스 규칙을 깊게 요구하지 않고, **주어진 위치/그림/힌트를 보고 배치하는 방식**을 우선 검토한다.
- Ghost는 물건을 들 수 있으므로 체스 말과의 상호작용을 어떻게 처리할지 별도 검토한다.

## 9. 설명이 필요한 방 — 벽 디스플레이를 이용한 무언어 튜토리얼

모든 퍼즐의 규칙을 텍스트로 설명하지 않는다.

플레이어가 별도의 언어를 읽지 않아도 이해할 수 있도록 **벽의 디스플레이에 행동을 설명하는 그림/아이콘**을 표시하는 방을 만들 수 있다.

### 기본 방향

- 방에 들어가면 벽에 디스플레이가 있다.
- 디스플레이에는 **비상 탈출구의 사람 모양 아이콘처럼 직관적인 그림**이 표시된다.
- 그림만 보고 플레이어가 어떤 행동을 해야 하는지 이해할 수 있어야 한다.
- 긴 문장이나 설명문을 최소화한다.
- 실제 게임플레이에서 가능한 행동을 그림으로 표현한다.

### 예시

#### 도끼 퍼즐

```text
[ 사람 ] + [ 도끼 ]
        ↓
     [ 나무 ]
        ↓
      [ ? ]
```

또는

```text
🧍 → 🪓 → 🌲
```

#### 버튼 퍼즐

```text
🧍 → 🔘
```

#### 밸브 퍼즐

```text
🧍 → 🔧 → ⚙
```

#### 물 채우기

```text
🪣 → 💧 → 🐟
```

### 목적

- 플레이어에게 퍼즐의 목표와 필요한 행동을 직관적으로 전달한다.
- 텍스트를 읽지 않아도 게임을 이해할 수 있게 한다.
- 설명 자체가 게임 세계 안에 존재하도록 한다.
- 방마다 필요한 경우에만 사용한다.
- 모든 방에 튜토리얼 디스플레이를 넣어 과도하게 설명하지 않는다.

## 10. Ghost와 도구 시스템

> **이미 구현되어 출시된 규칙이다.** 여기는 기록이고, 규칙의 위치는 `CLAUDE.md` §4다.

Ghost도 플레이어와 동일하게 필요한 도구를 가지고 있어야 특정 작업을 수행할 수 있다는 규칙을 유지한다.

예:

- Pin → 풍선 터뜨리기
- Axe → 나무 베기
- Wrench → 밸브 조작
- Bucket → 물 운반
- Key → 문/잠금장치
- 기타 도구 → 해당 도구가 필요한 상호작용

### 방향

- Ghost가 먼저 특정 장소에 도착했다고 해서 자동으로 작업을 수행하지 않는다.
- 해당 iteration에서 Ghost가 실제로 도구를 획득하고 들고 있어야 한다.
- "Ghost가 할 수 있는가?"와 "Ghost가 필요한 도구를 가지고 있는가?"를 별개의 조건으로 취급한다.
- 도구를 이용한 행동 자체가 iteration 설계의 일부가 되도록 한다.

## 11. Ghost의 역할 분담

Ghost를 단순한 반복 애니메이션이 아니라 **과거의 나에게 맡겨진 역할**로 느끼게 한다.

예:

```text
Ghost 1 → 버튼 담당
Ghost 2 → 밸브 담당
Ghost 3 → 도끼질 담당
Ghost 4 → 문 담당
Ghost 5 → 물 운반 담당
```

- 각 iteration에서 플레이어가 자신의 행동을 계획한다.
- 이후 iteration에서는 그 행동을 Ghost가 반복한다.
- 플레이어가 Ghost에게 직접 명령하는 시스템은 추가하지 않는다.
- 플레이어 자신의 과거 행동을 "미리 프로그래밍하는 것"처럼 느껴지게 하는 방향을 유지한다.

## 12. 방별 퍼즐 유형 분리

각 방이 같은 종류의 버튼/레버 퍼즐만 반복하지 않도록 한다.

후보:

```text
Room 1
→ 동시성 / 기본 Ghost 협력

Room 2
→ 도구 / 물건 / 열쇠 / 공간 확장

Room 3
→ 누적 작업량 / 나무 / 대형 오브젝트

Room 4
→ 탐색 / 숫자 단서 / 조합

Final Room
→ 수집한 단서 결합 / 최종 탈출
```

정확한 배치는 플레이테스트 결과에 따라 결정한다.

## 13. Room 확장

> **무효.** 이 좌표 계획은 지금 구조와 맞지 않는다. 아래 '디자인 원칙' 만 유효하다.

현재 Room4 이후 추가 방을 넣을 경우:

- 기존 Room4를 뒤쪽으로 이동한다.
- 새로운 퍼즐 방을 기존 Room4 위치에 배치한다.
- 새로운 방은 `4 * RoomPitch` 위치에 배치한다.
- Room4의 남쪽 doorway는 유지한다.
- Room4의 북쪽은 계속 막혀 있어야 한다.
- `DoorPocketFill_4`를 유지/추가한다.
- `EscapeTrigger`는 새 마지막 퍼즐 방의 북쪽 threshold로 이동한다.

### 디자인 원칙

- 단순히 이동 거리를 늘리지 않는다.
- 빈 방은 이동 시간이 짧기 때문에 거리보다 **iteration 비용**을 증가시키는 방향으로 설계한다.
- 새로운 방은 Room3처럼 여러 iteration이 필요한 퍼즐을 우선한다.

## 14. 최종 iteration 연출

최종 iteration은 새로운 퍼즐을 푸는 시간이 아니라 **지금까지 쌓아온 Ghost들의 결과를 확인하는 시간**으로 설계한다.

예:

```text
최종 iteration 시작

Ghost 1 → 버튼 작동
Ghost 2 → 밸브 작동
Ghost 3 → 나무 베기
Ghost 4 → 문 열기
Ghost 5 → 장치 작동

현재 플레이어
→ 아무것도 하지 않음
→ 열린 길을 따라 이동
→ 최종 탈출
```

목표:

- 플레이어가 "내가 지금까지 했던 행동들이 전부 연결되어 있다"는 것을 시각적으로 확인한다.
- 여러 Ghost가 각자의 위치에서 동시에 행동하는 모습을 보여준다.
- 마지막 walk-through 자체를 게임의 보상으로 만든다.
- 최종 탈출 직전에는 가능한 한 새로운 조작/퍼즐을 요구하지 않는다.
- Ghost들이 모든 작업을 수행하고 있는 모습을 충분히 볼 수 있도록 한다.
- 마지막에는 플레이어가 그 결과를 따라 걸어가며 탈출한다.

---

## 15. 챕터 구조 여부

현재 방향에서는 **여러 챕터로 나누어 각각 새로운 iteration을 시작하는 구조보다 하나의 연속적인 iteration을 우선 검토한다.**

목표 구조:

```text
60초 제한
↓
Room 1
↓
Room 2
↓
Room 3
↓
Room 4
↓
Final Room
↓
탈출
```

- 반복할수록 Ghost가 누적된다.
- 공간과 퍼즐 해결 상태가 점점 완성된다.
- 최종 iteration에서 모든 Ghost가 필요한 역할을 수행한다.
- 챕터 분리는 플레이테스트 결과에 따라 추후 검토한다.

3. Ghost가 늘어나는 것이 실제로 도움이 된다고 느끼는가?
4. 여러 Ghost가 각자의 역할을 수행하는 장면이 재미있는가?
5. 최종 iteration에서 현재 플레이어가 아무것도 하지 않아도 성취감을 느끼는가?
6. 마지막 walk-through가 "기다리는 시간"이 아니라 "내가 만든 결과를 보는 시간"으로 느껴지는가?
7. 필요한 iteration 수가 지나치게 많아 grind처럼 느껴지지 않는가?
8. Ghost가 너무 많아졌을 때 화면이 복잡해지거나 혼란스럽지 않은가?
9. 그림 기반 설명만으로 새로운 퍼즐의 목표와 필요한 행동을 이해할 수 있는가?
10. 각 방의 퍼즐이 서로 다른 경험을 제공하는가?
