# Room3 구조 변경 및 레버 기반 퍼즐 기믹 구현

현재 Room3 관련 구조와 퍼즐 기믹을 아래와 같이 변경/구현해줘.

## 1. Room3_1 → Room3_2N 이동 구간 확장

기존 Room3_1과 Room3_2N 사이의 거리를 크게 늘린다.

두 방 사이에 **긴 통로**를 추가한다.

이 통로는 일반적인 문이 열리고 닫히는 구조가 아니라, 원래는 특정 구조물이 통로를 막고 있다가 이동하면서 통로가 열리는 형태다.

### 발판과 통로

Room3_1에 있는 발판을 플레이어가 밟고 있는 동안에만 통로가 열린 상태를 유지한다.

- 발판을 밟고 있음 → 통로를 막고 있던 구조물이 이동하여 통로가 열린 상태
- 발판에서 내려옴 → 구조물이 즉시 원래 위치로 돌아와 통로를 막음
- 플레이어가 통로를 지나가는 도중 발판에서 떨어지면 구조물이 돌아와 통로를 막고 플레이어가 사망하도록 한다.

기존보다 이동 거리가 길어졌기 때문에 플레이어가 발판을 충분히 오래 밟고 있어야 통과할 수 있도록 구성한다.

기존 관련 동작 시스템이 있다면 최대한 활용하고, 이동 거리와 통로 구조를 확장하는 방향으로 구현한다.

---

## 2. Room3_2N 크기 확대

Room3_2N 방의 전체 크기를 현재보다 **2배로 확대**한다.

기존에 존재하는 요소와 기능은 가능한 한 유지하면서 공간을 확장한다.

---

# 3. Room3_N 퍼즐 기믹

Room3_N에는 플레이어가 위쪽으로 올라갈 수 있는 **색상별 패널/계단 구조**를 만든다.

색상은 다음 3가지다.

- Red
- Blue
- Yellow

각 색상에는 여러 개의 패널이 존재한다.

정확한 패널 개수는 현재 확정하지 않는다. 실제 플레이 테스트를 통해 적절한 개수를 조정할 수 있도록 유연하게 구현한다.

---

# 4. 색상별 레버

각 색상의 패널은 다른 방에 있는 해당 색상의 **레버(Lever)** 로 조작한다.

- Room3_2S → Red Lever → Red 패널
- Room3_2E → Blue Lever → Blue 패널
- Room3_2W → Yellow Lever → Yellow 패널

색상 연결 관계는 반드시 고정한다.

예:

- Red Lever → Red 패널만 제어
- Blue Lever → Blue 패널만 제어
- Yellow Lever → Yellow 패널만 제어

---

# 5. 레버 작동 방식

레버는 **Hold-to-Activate 방식**으로 구현한다.

플레이어가 레버를 당기고 있는 동안에만 해당 색상의 패널이 활성화된다.

예를 들어 Room3_2S의 Red Lever를 당기고 있는 동안:

- Room3_N의 모든 Red 패널이 실시간으로 돌출된다.
- 돌출된 Red 패널은 플레이어가 밟고 올라갈 수 있는 계단의 일부가 된다.

Red Lever를 놓는 순간:

- 모든 Red 패널이 즉시 원래 위치로 돌아간다.
- Red 계단도 즉시 사라진다.

Blue와 Yellow도 동일한 방식으로 동작한다.

### 중요

일반적인 Toggle 방식으로 구현하지 않는다.

즉:

`한 번 클릭 → 계속 활성화 → 다시 클릭 → 비활성화`

방식이 아니다.

반드시 다음과 같이 구현한다.

`레버를 잡고 당김 → 해당 색상 패널 활성화`

`레버에서 손을 놓음 → 해당 색상 패널 비활성화`

패널의 상태는 레버 입력과 **실시간으로 동기화**되어야 한다.

---

# 6. 패널은 실제 계단의 일부

Room3_N의 패널 자체가 플레이어가 올라갈 수 있는 **계단의 일부**가 된다.

패널이 활성화되면 단순히 색깔이나 조명만 변경되는 것이 아니라 실제 공간적으로 돌출되어 플레이어가 밟을 수 있어야 한다.

즉:

`레버를 당김`
→ `해당 색상의 모든 패널이 돌출`
→ `계단 형성`
→ `플레이어가 올라갈 수 있음`

레버를 놓으면:

`레버 해제`
→ `해당 색상의 모든 패널이 원위치`
→ `해당 계단 사라짐`

패널의 움직임은 플레이어가 현재 상태를 직관적으로 이해할 수 있도록 자연스럽고 명확하게 표현한다.

---

# 7. 퍼즐의 핵심

Room3_N에서는 단순히 레버를 당기면 계단이 생기고 그대로 올라가기만 하는 구조가 되면 안 된다.

**Room3_N의 구조 자체를 이용하여 특정 색상의 패널이 활성화되었을 때 다른 위치로 이동하기 어려워지거나, 다른 경로가 막히는 상황을 만든다.**

따라서 플레이어는 단순히 하나의 레버를 계속 당기는 것이 아니라 다음을 판단해야 한다.

- 현재 어떤 색상의 계단이 필요한가?
- 현재 위치에서 어떤 패널이 필요한가?
- 특정 색상의 패널이 활성화되면 어떤 이동 경로가 막히는가?
- 다음 위치로 이동하기 위해 어떤 레버를 언제 당겨야 하는가?
- 레버를 놓으면 어떤 계단이 사라지는가?

즉, **레버의 상태를 실시간으로 변경하면서 이동 경로를 만들어가는 퍼즐**이다.

구체적인 패널 개수와 최종 배치는 현재 확정하지 않는다.

실제 플레이 테스트가 가능하도록 먼저 합리적인 형태로 구현하고, 이후 플레이하면서 패널 수와 배치를 조정할 수 있도록 구성한다.

---

# 8. CCTV 시스템

Room3_2N에는 여러 개의 CCTV를 배치한다.

그리고 Room3_2S, Room3_2E, Room3_2W에서 각각 CCTV 화면을 볼 수 있도록 한다.

플레이어는 다른 방에 있는 상태에서 CCTV 화면을 확인하면서 Room3_N의 상황을 파악하고 레버를 조작할 수 있어야 한다.

CCTV는 단순한 장식이 아니라 **퍼즐 해결을 위한 핵심 정보 제공 장치**로 사용한다.

플레이어는 CCTV를 통해 최소한 다음 정보를 파악할 수 있어야 한다.

- Room3_N의 현재 패널 상태
- 현재 돌출되어 있는 계단
- 플레이어의 위치
- 이동 가능한 경로
- 퍼즐의 현재 진행 상황

---

# 9. 퍼즐 플레이 흐름

전체적으로 다음과 같은 플레이가 가능해야 한다.

1. 플레이어가 Room3_2S/E/W 중 하나에 위치한다.
2. 해당 방의 CCTV를 통해 Room3_N을 확인한다.
3. 필요한 색상의 레버를 당긴다.
4. Room3_N에서 해당 색상의 모든 패널이 실시간으로 돌출된다.
5. 플레이어는 돌출된 패널을 이용해 이동한다.
6. 다음 위치로 이동하기 위해 다른 색상의 레버가 필요할 수 있다.
7. 기존 레버를 놓으면 해당 색상의 패널이 즉시 원위치로 돌아간다.
8. CCTV를 다시 확인하며 다음 레버를 조작한다.
9. 색상별 패널의 상태를 적절한 타이밍에 변경하면서 Room3_N의 상부까지 도달한다.

이 과정에서 플레이어가 단순히 한 레버만 계속 당기면 해결되는 구조가 되지 않도록 Room3_N의 패널 배치를 설계한다.

---

# 10. 구현 시 중요 사항

기존 프로젝트의 구조와 시스템을 먼저 확인한다.

기존 Room3 관련 기능이 있다면 무조건 새로 만드는 대신 가능한 부분은 기존 시스템을 활용한다.

다음 사항을 반드시 지킨다.

1. 기존 Room3의 다른 퍼즐이나 기능을 임의로 삭제하지 않는다.
2. 기존 플레이어 이동 및 상호작용 시스템을 최대한 유지한다.
3. 기존에 사용할 수 있는 상호작용 시스템이 있다면 그것을 활용한다.
4. 색상별 레버와 패널의 연결 관계를 명확하게 분리한다.
5. 레버 입력은 반드시 Hold-to-Activate 방식으로 구현한다.
6. 레버 상태와 패널 상태는 실시간으로 동기화한다.
7. 레버를 놓는 순간 해당 색상의 패널이 원위치로 돌아오도록 한다.
8. 패널은 실제 Collider를 가진 이동 가능한 계단으로 동작해야 한다.
9. 패널 개수와 배치는 나중에 플레이 테스트를 통해 쉽게 조정할 수 있도록 구성한다.
10. Room3_2N의 크기는 기존의 2배가 되도록 한다.
11. Room3_1 → Room3_2N 사이의 통로는 기존보다 충분히 길게 만든다.
12. 통로를 막는 구조물은 발판을 밟고 있는 동안에만 열린 상태를 유지한다.
13. 발판에서 떨어지는 순간 구조물이 돌아와 통로를 막도록 한다.
14. 통로 안에서 구조물에 막히거나 충돌하는 경우 플레이어가 사망하도록 한다.
15. CCTV는 실제 퍼즐 해결에 사용할 수 있는 수준으로 Room3_N을 보여줘야 한다.

아직 확정하지 않은 패널 개수, 정확한 패널 배치, 최종 퍼즐 해답 등은 임의로 복잡하게 확정하지 않는다.

우선 실제 플레이가 가능한 기본 구조를 구현한 후, 플레이 테스트를 통해 패널 개수와 배치를 조정할 수 있도록 한다.
