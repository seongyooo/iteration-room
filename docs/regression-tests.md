# Regression tests

The project uses Unity Test Framework 1.7.0, bundled with Unity 6000.5.7f1.
`Assets/Scripts/IterationRoom.Runtime.asmdef` lets tests reference production types directly.
It references uGUI and URP; editor tools retain their predefined editor assembly.
Existing script GUIDs remain unchanged. Scenes continue to be generated by SceneBuilder.

## Run

In Unity, open **Window > General > Test Runner** and run the EditMode and PlayMode tabs.
For unattended runs, close Unity and run from the repository root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/Run-RegressionTests.ps1
```

Use `-Mode EditMode` or `-Mode PlayMode` to run one suite. `-UnityPath` overrides the
editor executable and `-TimeoutSeconds` sets the per-suite limit (default 600).
The execution-policy option applies only to that PowerShell process.
Logs and NUnit XML reports go to ignored `TestResults/`, with unique filenames so
an old successful result cannot mask a failed run. Missing results, zero tests,
timeouts, nonzero exit codes, or a result other than Passed fail the command.

## Coverage

- EditMode: both fullscreen transitions preserve the chosen resolution; hidden
  credits, record and cycle pages reject Submit and opening them disables the main menu.
- PlayMode: a full hand rejects another item; a surrendered socket item returns to its
  original parent, position and scale; player/ghost and ghost/ghost handovers revoke
  the old holder's tool use; skipped ticks drain carry events in order; resetting playback
  rewinds those events and releases held items; interaction claims expire next frame.
  Empty hands do not advertise a lock while held objects do; destroying a loop manager
  clears the actual managed singleton reference, not only Unity's fake-null comparison.

Tests construct small disposable objects, not the generated game scenes. EditMode tests
restore the three resolution preferences they touch. PlayMode fixtures unregister their
items and release custody before destroying their objects. Gameplay assertions call public
production APIs; only private menu navigation is invoked via reflection, because menu
callbacks are private and invoking Awake would also change global audio settings.

## Limits

Verified on 2026-09-06 with Unity 6000.5.7f1: EditMode **14/14 passed** and
PlayMode **10/10 passed**, with no skipped tests. The sandboxed launch stalled at
license initialization; the authorized launch outside the sandbox completed both suites.

The added feedback suite checks centered 16:9 viewports, staged display application,
generated scene wiring, standing-tree collision/reset, and first-release hint retirement.
Scene tests require the generated MainMenu, IterationRoom, Cycle2 and Cycle3 scenes;
on a fresh checkout run SceneBuilder before the suite. Preview scenes are closed after each test.

These tests cover components and their interactions, not a complete LoopManager cycle,
the full input aim competition, lighting, performance, or the ending route. Passing them
does not establish that generated scenes have valid bindings or that puzzles feel right.
Follow up with scene generation and human play testing after architectural/content changes.
Unity must import and compile the new assemblies before tests can be discovered. A standalone
C# compile is useful syntax/reference validation but is not a passing Unity test run.

Framework assembly setup follows the [Unity Test Framework documentation](https://docs.unity.cn/Packages/com.unity.test-framework@1.4/manual/workflow-create-test-assembly.html).
